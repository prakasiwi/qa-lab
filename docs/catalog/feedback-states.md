| ID     | Behavior                           | Aturan Standar                                                                                                                                                                                                                |
| ------ | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FDB-01 | Kondisi awal                       | Sebelum proses dimulai, tampilkan instruksi atau aksi yang dapat dilakukan jika diperlukan. Jangan menampilkan status berhasil, gagal, atau hasil kosong sebelum pemeriksaan dilakukan.                                       |
| FDB-02 | Loading awal                       | Saat data pertama kali dimuat, tampilkan indikator loading pada area terkait. Data belum dianggap kosong sebelum pemuatan selesai.                                                                                            |
| FDB-03 | Memuat ulang data                  | Saat data diperbarui, tampilkan indikator proses. Jika data sebelumnya tetap ditampilkan, tandai bahwa pembaruan berlangsung agar tidak dianggap sebagai hasil terbaru.                                                       |
| FDB-04 | Cakupan loading                    | Indikator loading dan pembatasan interaksi hanya berlaku pada area yang sedang diproses, kecuali proses memang mengharuskan seluruh halaman menunggu.                                                                         |
| FDB-05 | Aksi sedang diproses               | Tombol pemicu menampilkan status yang sesuai, seperti “Menyimpan…”, dan tidak dapat diaktifkan berulang selama proses berlangsung.                                                                                         |
| FDB-06 | Progres terukur                    | Jika progres dapat dihitung, tampilkan persentase atau jumlah yang selesai. Jika tidak dapat dihitung, gunakan indikator proses tanpa persentase perkiraan.                                                                   |
| FDB-07 | Proses diterima                    | Jika permintaan baru masuk antrean atau memulai proses lanjutan, tampilkan “Permintaan diterima” atau “Sedang diproses”. Jangan menyatakan seluruh proses berhasil sebelum selesai.                                       |
| FDB-08 | Proses berhasil                    | Pesan berhasil ditampilkan setelah hasil akhir dikonfirmasi oleh server atau proses terkait. Pesan menjelaskan aksi yang selesai dilakukan.                                                                                   |
| FDB-09 | Data belum tersedia                | Jika pemuatan berhasil tetapi belum ada data, tampilkan empty state seperti “Belum ada invoice”. Sediakan aksi membuat data jika pengguna memiliki izin.                                                                    |
| FDB-10 | Hasil pencarian atau filter kosong | Jika tidak ada data yang sesuai dengan pencarian atau filter, tampilkan pesan yang menjelaskan kondisi tersebut dan sediakan cara mengubah atau mereset kriterianya.                                                          |
| FDB-11 | Kesalahan validasi                 | Kesalahan input ditampilkan di dekat field terkait dan menjelaskan cara memperbaikinya. Rincian perilaku mengikuti `form-validation.md`.                                                                                    |
| FDB-12 | Penolakan aturan bisnis            | Jika aksi ditolak karena kondisi bisnis, tampilkan alasan yang spesifik dan langkah lanjut jika tersedia. Contoh: “Invoice tidak dapat diubah karena sudah disetujui”.                                                      |
| FDB-13 | Gangguan koneksi                   | Jika koneksi tidak tersedia atau terputus, tampilkan informasi gangguan. Input dan data sebelumnya dipertahankan jika masih relevan.                                                                                          |
| FDB-14 | Gangguan server                    | Tampilkan pesan yang mudah dipahami tanpa membocorkan detail teknis sensitif. Jangan menampilkan stack trace, query database, atau kredensial.                                                                                |
| FDB-15 | Batas waktu terlampaui             | Jika waktu tunggu berakhir, tampilkan pesan timeout. Untuk aksi yang mengubah data, hasil tidak langsung dinyatakan gagal sebelum statusnya dapat dipastikan.                                                                 |
| FDB-16 | Mencoba kembali                    | Sediakan Retry jika proses dapat diulang. Percobaan ulang mempertahankan parameter yang relevan dan mengikuti aturan pencegahan proses ganda pada fitur terkait.                                                              |
| FDB-17 | Kegagalan sebagian                 | Jika sebagian proses berhasil, tampilkan ringkasan hasil berhasil dan gagal beserta langkah lanjut. Jangan memberikan satu pesan berhasil yang menutupi kegagalan sebagian.                                                   |
| FDB-18 | Akses ditolak                      | Jika akses tidak diizinkan, tampilkan pesan dan tujuan lanjutan sesuai `authorization.md`. Kondisi ini tidak ditampilkan sebagai gangguan koneksi atau server.                                                              |
| FDB-19 | Sesi berakhir                      | Jika sesi tidak lagi valid, jelaskan bahwa pengguna perlu login kembali. Penanganan mengikuti `authentication-session.md`.                                                                                                  |
| FDB-20 | Penempatan pesan                   | Pesan field ditempatkan dekat field; pesan khusus area ditempatkan pada area terkait; pesan hasil aksi umum dapat menggunakan toast. Informasi yang membutuhkan tindakan tidak hanya ditampilkan dalam toast sementara.       |
| FDB-21 | Durasi pesan                       | Pesan berhasil yang tidak membutuhkan tindakan boleh hilang otomatis sesuai durasi yang telah ditentukan. Pesan kesalahan atau peringatan yang membutuhkan tindakan tetap tersedia sampai diselesaikan atau ditutup pengguna. |
| FDB-22 | Kejelasan pesan                    | Pesan menjelaskan apa yang terjadi dan tindakan yang dapat dilakukan. Gunakan istilah yang konsisten dengan label fitur dan bahasa aplikasi.                                                                                  |
| FDB-23 | Peringatan                         | Gunakan peringatan untuk kondisi yang perlu diperhatikan tetapi belum tentu menghentikan proses. Jelaskan konsekuensi dan pilihan tindakan yang tersedia.                                                                     |
| FDB-24 | Pembatalan proses                  | Proses hanya ditampilkan sebagai “Dibatalkan” setelah pembatalan dikonfirmasi. Menutup dialog atau meninggalkan halaman tidak otomatis berarti proses di server dibatalkan.                                                 |
| FDB-25 | Perubahan status                   | Saat proses selesai, indikator loading dihentikan dan kontrol diperbarui sesuai hasil serta izin pengguna. Pesan lama yang tidak lagi relevan dibersihkan.                                                                    |
| FDB-26 | Respons berurutan                  | Feedback mengikuti permintaan terbaru yang masih relevan. Respons lama tidak boleh menampilkan pesan atau status yang bertentangan dengan kondisi aktif.                                                                      |
| FDB-27 | Aksesibilitas feedback             | Status tidak hanya dibedakan berdasarkan warna. Gunakan teks atau ikon pendukung, dan pastikan perubahan penting dapat dikenali pengguna pembaca layar tanpa memindahkan fokus secara tiba-tiba.                              |
