| ID     | Behavior                         | Aturan Standar                                                                                                                                                                                                                              |
| ------ | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SUB-01 | Pemicu pengiriman                | Form dikirim ketika pengguna mengaktifkan tombol Submit atau Save. Nama tombol mengikuti tujuan aksi.                                                                                                                                       |
| SUB-02 | Validasi sebelum pengiriman      | Seluruh field yang berlaku diperiksa sebelum pengiriman. Jika terdapat kesalahan, pengiriman dihentikan dan pesan ditampilkan sesuai katalog validasi.                                                                                      |
| SUB-03 | Hak akses pengiriman             | Server memastikan pengguna masih memiliki hak untuk menjalankan aksi saat permintaan diproses. Jika tidak, permintaan ditolak tanpa menyimpan perubahan.                                                                                    |
| SUB-04 | Data yang dikirim                | Pengiriman menggunakan nilai terbaru pada form saat Submit dijalankan. Field yang boleh diproses ditentukan dan diperiksa oleh server.                                                                                                      |
| SUB-05 | Konfirmasi aksi                  | Jika aksi memerlukan konfirmasi, tampilkan ringkasan tindakan sebelum pengiriman. Memilih Batal menutup konfirmasi tanpa mengirim atau menghapus input.                                                                                     |
| SUB-06 | Status pengiriman                | Selama pengiriman berlangsung, tampilkan indikator proses dan ubah tombol menjadi tidak dapat diaktifkan kembali.                                                                                                                           |
| SUB-07 | Perubahan saat pengiriman        | Field yang memengaruhi data kiriman tidak dapat diubah selama pengiriman berlangsung, agar nilai yang terlihat sesuai dengan nilai yang dikirim.                                                                                            |
| SUB-08 | Pencegahan pengiriman ganda      | Klik berulang atau permintaan ulang untuk aksi yang sama tidak boleh menghasilkan penyimpanan atau proses bisnis ganda. Pencegahan diterapkan pada antarmuka dan server.                                                                    |
| SUB-09 | Penyimpanan berhasil             | Keberhasilan ditampilkan setelah server mengonfirmasi bahwa data berhasil disimpan atau aksi berhasil dijalankan.                                                                                                                           |
| SUB-10 | Feedback berhasil                | Tampilkan pesan yang menjelaskan hasil aksi, misalnya “Data pengguna berhasil ditambahkan”.                                                                                                                                               |
| SUB-11 | Kondisi setelah berhasil         | Setelah berhasil, form ditutup, dikosongkan, atau diarahkan ke halaman tujuan sesuai ketentuan FSD.                                                                                                                                         |
| SUB-12 | Pembaruan data tampilan          | Daftar atau detail terkait diperbarui agar menampilkan hasil penyimpanan terbaru. Pencarian, filter, dan sortir aktif tetap dipertahankan jika pengguna kembali ke daftar.                                                                  |
| SUB-13 | Kesalahan validasi server        | Jika server menolak input karena validasi, tampilkan kesalahan pada field terkait dan pertahankan input agar dapat diperbaiki.                                                                                                              |
| SUB-14 | Penolakan aturan bisnis          | Jika aksi tidak memenuhi aturan bisnis, tampilkan alasan yang dapat dipahami. Contoh: transaksi tidak dapat diubah karena sudah disetujui.                                                                                                  |
| SUB-15 | Gangguan koneksi atau server     | Jika pengiriman gagal, tampilkan pesan gagal dan pertahankan input. Setelah proses berakhir, kontrol form dapat digunakan kembali sesuai hak akses dan kondisi data.                                                                        |
| SUB-16 | Hasil pengiriman belum diketahui | Jika koneksi terputus atau timeout setelah permintaan dikirim, jangan langsung menyatakan penyimpanan gagal. Informasikan bahwa hasil belum dapat dipastikan dan periksa status sebelum melakukan pengiriman ulang.                         |
| SUB-17 | Mencoba kembali                  | Pengguna dapat mencoba kembali setelah kendala diselesaikan. Percobaan ulang tidak boleh menggandakan hasil dari permintaan sebelumnya yang ternyata sudah berhasil.                                                                        |
| SUB-18 | Sesi kedaluwarsa                 | Jika sesi kedaluwarsa, hentikan pengiriman yang belum diotorisasi dan arahkan pengguna untuk login kembali. Pemulihan input setelah login mengikuti kententuan yang telah ditetapkan dan tidak menyimpan data sensitif secara sembarangan. |
| SUB-19 | Data berubah oleh pengguna lain  | Jika versi data telah berubah sejak form dibuka, cegah penimpaan tanpa pemberitahuan. Tampilkan informasi konflik dan minta pengguna memuat data terbaru sebelum menyimpan kembali.                                                         |
| SUB-20 | Penyimpanan satu kesatuan        | Jika satu Submit mencakup beberapa perubahan yang harus berhasil bersama, seluruh perubahan disimpan sebagai satu kesatuan. Jika salah satu gagal, tidak ada perubahan sebagian yang tersimpan.                                             |
| SUB-21 | Proses lanjutan                  | Jika Submit hanya memulai proses lanjutan, tampilkan status “Sedang diproses” atau “Permintaan diterima”. Jangan menyatakan seluruh proses selesai sebelum hasil akhirnya tersedia.                                                     |
| SUB-22 | Batal sebelum pengiriman         | Tombol Cancel menutup atau meninggalkan form. Jika terdapat perubahan yang belum disimpan, tampilkan konfirmasi sebelum membuang perubahan.                                                                                                 |
| SUB-23 | Meninggalkan form saat proses    | Jika pengguna meninggalkan form saat pengiriman berlangsung, jangan menganggap proses di server otomatis dibatalkan. Saat kembali, tampilkan status data terbaru.                                                                           |
| SUB-24 | Form tanpa perubahan             | Pada form edit, tombol Save tidak aktif sampai terdapat perubahan nilai yang akan disimpan.                                                                                                                                                 |
