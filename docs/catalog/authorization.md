| ID     | Behavior                       | Aturan Standar                                                                                                                                                                                                     |
| ------ | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ACL-01 | Akses default                  | Akses hanya diberikan jika terdapat aturan yang mengizinkan. Permission yang belum ditetapkan dianggap tidak diizinkan.                                                                                            |
| ACL-02 | Pemeriksaan di server          | Server memeriksa hak akses pada setiap permintaan terlindungi. Menyembunyikan menu atau tombol saja tidak cukup untuk membatasi akses.                                                                             |
| ACL-03 | Akses menu                     | Menu hanya ditampilkan jika pengguna memiliki akses ke halaman tujuan. Menu induk ditampilkan jika terdapat minimal satu submenu yang dapat diakses.                                                               |
| ACL-04 | Akses halaman                  | Pengguna hanya dapat membuka halaman yang diizinkan, termasuk ketika mengakses melalui URL langsung. Jika ditolak, tampilkan halaman akses ditolak atau tujuan pengganti sesuai yang telah ditentukan.             |
| ACL-05 | Akses aksi                     | Hak melihat, menambah, mengubah, menghapus, mengimpor, mengekspor, dan menyetujui diperiksa secara terpisah sesuai daftar permission yang telah ditentukan.                                                        |
| ACL-06 | Akses melalui API              | Permintaan API untuk aksi yang tidak diizinkan ditolak tanpa menjalankan aksi atau mengembalikan data terlindungi.                                                                                                 |
| ACL-07 | Cakupan daftar data            | Daftar, pencarian, filter, jumlah data, dan pagination hanya mencakup data yang boleh diakses pengguna.                                                                                                            |
| ACL-08 | Akses detail data              | Hak akses diperiksa terhadap setiap data yang diminta. Mengganti ID pada URL atau permintaan tidak memberikan akses ke data pengguna lain.                                                                         |
| ACL-09 | Kepemilikan data               | Jika akses dibatasi berdasarkan pemilik, pengguna hanya dapat menjalankan aksi pada data miliknya. Definisi pemilik dan pengecualian yang telah ditentukan.                                                        |
| ACL-10 | Batas organisasi               | Pengguna hanya dapat mengakses data organisasi, perusahaan, cabang, atau project yang menjadi cakupan aksesnya. Identitas organisasi pada permintaan tetap diperiksa oleh server.                                  |
| ACL-11 | Akses field                    | Field sensitif hanya ditampilkan atau dikembalikan kepada pengguna yang berhak. Menyembunyikan field pada tampilan tidak boleh menyisakan nilainya pada respons API yang tidak diizinkan.                          |
| ACL-12 | Hak mengubah field             | Server hanya menerima perubahan pada field yang boleh diubah pengguna. Penambahan field lain dalam permintaan tidak boleh mengubah data yang dilindungi.                                                           |
| ACL-13 | Opsi referensi                 | Pilihan pada dropdown, autocomplete, dan pemilih data hanya memuat referensi yang boleh digunakan pengguna. Nilai yang dikirim tetap diperiksa kembali oleh server.                                                |
| ACL-14 | Akses file                     | Hak melihat, mengunduh, mengganti, dan menghapus file mengikuti akses terhadap file serta data terkait. Mengetahui URL file tidak otomatis memberikan izin.                                                        |
| ACL-15 | Impor dan ekspor               | Impor hanya memproses data dalam cakupan izin pengguna. Ekspor hanya memuat baris dan kolom yang boleh diakses.                                                                                                    |
| ACL-16 | Aksi massal                    | Hak akses diperiksa terhadap setiap data dalam aksi massal. Pemilihan beberapa ID tidak boleh melewati pembatasan yang berlaku pada aksi satuan.                                                                   |
| ACL-17 | Kondisi dan status data        | Permission tetap tunduk pada aturan bisnis. Contoh: memiliki izin Edit tidak otomatis memperbolehkan perubahan transaksi yang sudah disetujui.                                                                     |
| ACL-18 | Beberapa role                  | Jika pengguna memiliki beberapa role, cara menghitung izin efektif yang telah ditentukan, misalnya gabungan role atau hanya role yang sedang aktif.                                                                |
| ACL-19 | Pergantian role atau workspace | Setelah pengguna berganti role atau workspace, akses dihitung ulang. Halaman dan data dari konteks sebelumnya tidak boleh tetap tersedia jika tidak diizinkan pada konteks baru.                                   |
| ACL-20 | Perubahan hak akses            | Penambahan atau pencabutan izin berlaku dalam batas waktu yang telah ditentukan. Setelah berlaku, server menggunakan izin terbaru meskipun halaman pengguna belum di-refresh.                                      |
| ACL-21 | Role atau keanggotaan nonaktif | Role, assignment, atau keanggotaan yang dinonaktifkan tidak lagi memberikan akses. Jika masih ada sumber izin lain yang valid, akses dihitung ulang berdasarkan sumber tersebut.                                   |
| ACL-22 | Pengelolaan hak akses          | Pengguna hanya dapat memberikan atau mencabut role dan permission dalam batas kewenangannya. Permintaan yang mencoba memberikan hak di luar kewenangan ditolak oleh server.                                        |
| ACL-23 | Pemisahan kewenangan           | Jika fitur mensyaratkan pemisahan tugas, pengguna tidak dapat menjalankan kombinasi aksi yang dilarang. Contoh: pembuat transaksi tidak boleh menyetujui transaksinya sendiri.                                     |
| ACL-24 | Respons akses ditolak          | Penolakan memberikan informasi yang cukup tanpa mengungkapkan detail data yang dilindungi. Untuk data di luar cakupan, aplikasi dapat menampilkan “Data tidak ditemukan” sesuai kebijakan yang telah ditentukan. |
| ACL-25 | Gagal memeriksa izin           | Jika izin tidak dapat diverifikasi karena gangguan layanan, aksi terlindungi tidak dijalankan. Tampilkan pesan gangguan dan opsi mencoba kembali.                                                                  |
| ACL-26 | Riwayat perubahan izin         | Perubahan role, permission, dan keanggotaan dicatat beserta pelaku, target, waktu, serta perubahan yang dilakukan. Rincian pencatatan mengacu pada `audit-trail.md`.                                             |
